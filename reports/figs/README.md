# 配图说明

本目录存放控制算法报告用到的图表。

## 文件

| 文件 | 用途 | 用在哪 |
|---|---|---|
| `fig_block.png` | 控制系统变量结构图（含两个待辨识函数 f、g） | 阶段一 图1 / 阶段二 图1 |
| `fig_step_response.png` | 二阶系统阶跃响应，六个阻尼比对比 | 阶段一 图2 |
| `fig_metrics.png` | 超调量、调节时间随阻尼比的变化；理论式与仿真量取的差异 | 阶段一 图3 / 阶段二 图3 |
| `fig_pid_sim.png` | 增量式 PID 温控仿真时程（温度／阀开度／误差） | 阶段二 图2 |
| `pid_sim.npz` | 上面那张图的原始仿真数据 | 中间数据 |
| `PID仿真.py` | 生成 `pid_sim.npz` 的仿真脚本 | 可复现 |
| `生成配图.py` | 由数据生成全部 4 张 PNG | 可复现 |

## 怎么重新生成

```bash
cd reports/figs
python PID仿真.py      # ① 先跑仿真，生成 pid_sim.npz
python 生成配图.py      # ② 再画图，覆盖 4 张 PNG
cd ..
xelatex 阶段一_控制算法.tex && xelatex 阶段一_控制算法.tex
xelatex 阶段二_控制算法.tex && xelatex 阶段二_控制算法.tex
```

**注意顺序**：必须先生成 `pid_sim.npz`，再画图，否则 `生成配图.py` 会因找不到数据文件报错。

## 仿真参数（改参数时两处要同步改）

`PID仿真.py` 里的参数**必须与阶段二报告「表 仿真工况与控制器参数」一致**，否则图与表会对不上：

| 参数 | 取值 |
|---|---|
| 目标温度 | 68 ℃ |
| 热源基础温度 / 波动幅度 | 82 ℃ / ±12 ℃ |
| 热源波动周期 | 15 s |
| 初始温度 / 环境温度 | 50 ℃ / 25 ℃ |
| 加热系数 a | 0.45 |
| 散热系数 k | 0.03（全关）~ 0.20（全开） |
| PID 参数 | Kp=8.0, Ki=0.5, Kd=2.0 |
| 控制周期 | 50 ms |

**改完之后**：重跑 `PID仿真.py`，把输出打印的结果数值同步更新到报告的「闭环仿真结果」表里。

## 关键结论（图里要能看出来）

`fig_pid_sim.png` 的核心作用是支撑「**超调不是积分饱和造成的，而是执行器能力上限造成的**」这个判断：

- 中间那幅图（阀开度）要能看出**峰值段阀已开到 100% 并持续了一段时间**（仿真中占 29.3%）
- 最上面那幅图要能看出**温度在阀饱和期间仍在上升**（峰值超调 +3.9 ℃）

这两点合起来才说明：控制器已经尽力，是执行器到顶了。
